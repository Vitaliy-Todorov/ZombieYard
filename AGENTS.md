# ZombieYard · инструкции агенту

ZombieYard — игра от первого лица о выживании на разрушаемом участке. Начни с критерия приёмки, которого касается запрос. Полные правила и числовые значения приведены в [ТЗ v4](Docs/ZombieYard_TZ_v4.md), размещение файлов — в [карте проекта](Docs/ARCHITECTURE.md), версии и назначение пакетов — в [техническом стеке](Docs/TECH_STACK.md).

## Как вести задачу

- При входе в проект используй [README](README.md). Для вопросов о готовности механик сверь [состояние реализации](Docs/IMPLEMENTATION_STATUS.md) с текущим кодом. Изменения согласованных правил игры отражай в [журнале решений](Docs/DECISIONS.md).
- Текущий запрос задаёт объём работы. ТЗ описывает поведение игры. При обсуждении архитектуры оформляй решение, а реализацию начинай по запросу на реализацию.
- Перед изменением проследи один сценарий от действия игрока или события мира до результата. Найди владельца состояния, место создания объекта и момент завершения его жизни. Добавляй класс, интерфейс или сервис, когда можешь назвать его первого потребителя.
- Фактическое состояние проверяй по сцене, префабам, конфигам и коду ZombieYard. Worldseed служит примером организации разработки. Имена планируемых папок и классов в карте проекта описывают будущую реализацию.
- После изменения укажи, какой критерий проверен и каким способом. Обновляй соответствующий документ, когда меняются границы ответственности, расположение файлов или состав зависимостей.

## Правила реализации

- Храни баланс в восьми типах конфигов из ТЗ. Загружай стартовые значения при создании попытки. Текущие HP принадлежат экземпляру цели, магазин — экземпляру оружия, слоты и запас патронов — игроку, расписание и учёт живых зомби — сервису спавна. Два зомби с одним конфигом должны получать урон независимо.
- Собирай зависимости в сценовом `GameLifetimeScope` через VContainer. Передавай зависимости обычным C#-классам через конструктор. Оставляй ввод, физические запросы, коллайдеры и отображение на стороне Unity. Подписки и таймеры завершай вместе с их владельцем.
- Проводи весь урон через общий `Health`. Значение берётся из `AttackConfig` для ближнего удара и из `AmmoConfig` для каждого попавшего снаряда. Событие обнуления срабатывает один раз. Блок освобождает ячейку, зомби запускает выпадение лута и освобождает место в лимите, смерть игрока завершает попытку.
- Используй общий `Pickup` для оружия и патронов. Патроны переходят в запас при приближении с любой стороны. Для оружия игрок смотрит на предмет и нажимает E. Проверяй дистанцию из `PlayerConfig` и результат передачи в слоты или запас до удаления предмета со сцены. Кулаки доступны через настройки пустого слота.
- Регистрируй один `ZombieSpawnService` на попытку. Точки за забором предоставляют позиции. При достижении лимита сервис пропускает создание и планирует следующую попытку. Для поведения зомби используй текущую позицию игрока, дальность атаки, допустимую высоту и длительность перелезания. Волны, зоны, зрение и слух находятся за границами v1.
- При перемещении ассетов используй Unity Editor, чтобы сохранить GUID. Проверяй сериализованные ссылки в сценах, префабах и настройках сборки. Генерацию `.meta`, файлов IDE и обёрток Input System оставляй Unity.

## Как проверять изменения

Для расчётов используй EditMode, для взаимодействия компонентов, физики и жизненного цикла сцены — PlayMode. Выбирай проверки по затронутому сценарию. Например, для дробовика проверь один потраченный патрон и три попадания из шести с суммой 36 урона при стартовом балансе. Для спавна достигни лимита, убери одного зомби и дождись следующего интервала. При изменении конфигов повтори сценарий с другим значением в инспекторе и начни новую попытку, чтобы проверить восстановление стартового состояния. Полный набор сценариев приёмки приведён в §11 ТЗ.
